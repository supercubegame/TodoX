# TodoX · 踩过的坑与测不出来的东西

这份文件从 `AGENTS.md` 里拆出来。理由：它是**随经验单调增长的档案**，而
`AGENTS.md` 是每次都要被读进上下文的**指令**。混在一起会让那条 200 行上限
反复顶格，然后有人去调宽它 —— 而调宽一条上限就是把断言改成装饰。

改代码之前读 [AGENTS.md](../AGENTS.md)。闸门红了读这里。

## 闸门红了先查夹具

命中率极高的排查顺序：**先问「这条断言的前提成立吗」，再问「产品对不对」。**
你在同时调试产品、尺子和环境，而尺子是新写的。已知的夹具坑：

- 轮询函数必须返回**布尔**。返回计数的话 0 会被当成「还没成立」等到超时。
- **第一个动作也要轮询。** 取窗口句柄那一刻应用可能还没初始化完。它是竞态，
  所以平时能过；输了那次会把后面所有步骤连带判成跳过。
- 设置类控件按一格要等一格。连按的话晚到的回写会把控件顶回旧值。
- **`capturePage` 会返回上一帧。** DOM 断言过了不代表画面跟上了，截图动作本身
  也要轮询到像素与 DOM 一致为止。实测：「搜索后只剩 1 行」那张图里是 3 行，
  而「三张图互不相同」照样全绿（它们确实互不相同，只是每张都晚了一步）。
- xvfb 默认 8 位色深，会让像素计数掷骰子。workflow 里显式要了 24 位。
- CI runner 默认**不带中日韩字体**。中文全变方块时，坏的是环境不是产品。
- 后台窗口会被节流。夹具在操作前显式 `show()` + `focus()`。
- **静态扫描 workflow 之前先剥 YAML 注释，并且剥完自证。** 犯过一次：说明注释里
  写着 `stdout-<slug>.log`，「日志名集合等于 GATES」就多出一个字面量 slug。同一形状
  还有一次：注释块被算进上一个 job,凡是「这段里不该出现 X」都去读具体那一行。
- 从配置里读出来的字面量拼进正则前要转义。邮箱里的 `.` 和 `+` 是元字符，
  不转义会让断言在一个「看起来匹配了」的地方悄悄放宽。
- 密钥扫描只看文本文件。把 PNG 也扫进去会给出偶发的、谁也看不懂的红。
- **性能数字先看校准那条。** 时间类断言红了先问「这台机器这次是不是特别慢」，
  校准系数写在报告第一行；比值类断言红了才大概是真的复杂度退化。
- **attest 红了先分清两件事**：是评论真的没送达（去看 summary 那个 job），
  还是 marker 两处不一致（快闸门那条会同时红，先看它）。
- **改了流程顺序，先问一句「审计还找得到它吗」。** 犯过一次：把发布改成草稿
  优先，而按 tag 查询对草稿返回 404（草稿没有 tag ref），审计当场读不到。
- **规矩文件顶到行数上限时，压措辞或者拆文件,不许调宽上限。** 实测：写完一轮
  文档它涨到 202 行，那条断言当场红。调宽是把断言改成装饰。这次是拆文件（就是
  你正在读的这份）。

### 一个 run 都没有

这个症状和「还没开始跑」在面板上长得一模一样，所以它自己就是一条沉默通道。
按这个顺序查：

1. **先看提交信息。** 平台会跳过 commit message 里带跳过标记（`skip ci` / `ci skip` /
   `no ci` 那几个方括号写法）的**整条 run**。实测踩过，而且就发生在「把那个字符串
   守卫删掉」的 PR 里 —— 提交信息里引用了那个字面量。**要在提交信息里谈它，就绕开
   字面量。**
2. **看分支名对不对得上触发范围。** `screenshots.yml` 只认 `docs/**` 与 `shots/**`；
   `release.yml` 只认 `release/**`。反过来也要留意：开一条叫 `docs/xxx` 的分支会
   **顺带触发截图流水线**，那大概不是你想要的。
3. **看 PR 是不是被 squash 合走了。** 那样你后面几个提交会落在一条孤立分支上，
   症状一样。发现孤立时诚实地说「这些值得救，那些直接废掉」。
4. 最后才怀疑 workflow 文件语法。

## 测不出来的

诚实列出来，免得后来者去补一个补不上的洞，或者更糟 —— 加一条启发式假装补上了。

> **这一节自己有一条纪律：往里加东西之前，先真的去试一次，并写清是哪天试的、
> 怎么试的。** 一条**错的**「测不出来」比没写更危险 —— 它会让那个方向永久失去
> 监督，而且看起来像是已经想清楚了。没人会去核对一件已经宣布无法核对的事。
>
> 这条纪律是买来的。2026-08-14 逐条复核这一节，抓到一条假结论（见下面
> 「多屏坐标」那条的删除说明）；同一天在备份仓抓到另一条，代价是那个每周
> 巡检的 agent 从创建起就没有定时，而没有任何东西会喊。
>
> 复核的手法：**别读代码判断「能不能测」，直接造一个变异体喂进去。** 变异体
> 活下来就是覆盖缺口，而覆盖缺口和空断言在报告上长得一模一样,都是全绿。

- **界面好不好看、顺不顺手**，机器判断不了。闸门只能证明「画出来了、点得动、
  数据对」，不能证明「好用」。
- **共享回写自己的行为对不对。** 这边守住了静态那半（钉 SHA、marker 一致、attest 在）
  和运行时那半（评论真送达且钉在本次）。**上游那份文件内部的逻辑管不着**,那只有
  `ci-workflows` 自己的自检负责。
  *（2026-08-14 核实：那个自检真的存在且不是装饰 —— `selftest.yml` 起一个假调用方跑
  完整条链路，三条用例：完整报告送达并带 composer 哨兵、同一个 marker 连发两遍必须
  更新而不刷屏、降级路径必须送达且真的变红。它 `uses` 的是本地路径，验的是本次改动。）*
- **「被钉住的那个 SHA，它的自检当时是绿的」没有任何断言在看。** 上一条说明自检
  存在，但我们这边只断言「钉的是 40 位 SHA、四份钉同一个」,钉一个自检红着的
  提交完全合规。这是 2026-08-14 复核时新发现的洞，不是原来就列着的。
  真解法是回写 workflow 自己带个版本标记，或者 bump 的时候人工去看一眼那次自检。
- **截图回写的循环守卫从没被真的触发过。** 它现在是身份判断（比字符串硬），但用
  GITHUB_TOKEN 推的提交本来就不触发 workflow,这条守卫在当前配置下可能永远走不到。
  它防的是「有人换成 PAT」那天。属于「够不着的边界」。
  **注意手动 dispatch 也验不了它**：`workflow_dispatch` 的事件载荷里根本没有
  `head_commit`，那一层比较会拿空值去比，恒为真。要真验只能换 PAT 推一次。
  *（2026-08-14 核实：这条成立。那条 `docs/split-agents` 分支上 bot 提交的 committer 是
  `41898282+github-actions[bot]@...` 且没带任何跳过标记，而它一个 run 都没触发 ——
  「GITHUB_TOKEN 推的提交不触发 workflow」是实测过的，不是查文档推的。）*
- **macOS 与 Windows 上的真实观感与原生行为**（菜单、Dock、任务栏、高 DPI）。
  CI 只验证「能打出包、体积合理、Release 上真的有这个文件」，行为验收得在真机上做。
- **安装包没有签名，装机流程验不了。** macOS Gatekeeper 与 Windows SmartScreen
  的拦截行为、以及绕过之后能不能正常启动，只有真机点得出来。
- **`.deb` 在各发行版上的依赖解析**、AppImage 在没有 FUSE 的机器上的表现。
- **绝对的性能数字。** 共享 runner 抖动能到好几倍，性能闸门只能证明「复杂度没退化、
  稳态延迟还在同一个量级」。渲染进程的帧率、启动时间同样没有断言在看。
- **撤销在真实使用里够不够用**。50 步是猜的，不是实测的。跨重启的撤销是有意不做的。
- **截图的「好看」程度**。像素计数与字形签名能证明「颜色对、字画出来了」，
  但区分不了「布局正常」和「布局错乱但颜色和字都还在」。
- **窗口在真实窗口管理器下的行为**：吸附、多显示器之间拖动、运行中切换 DPI 缩放。
  CI 里跑的是没有窗口管理器、只有一个屏的 xvfb，这些**交互**验不了。
  ~~`clampBounds` 的多屏分支在那里根本走不到。~~ **这半句是错的，2026-08-14 删掉。**
  `clampBounds` 是纯函数，`area` 只是个普通参数 —— 快闸门想喂什么工作区就喂什么，
  端到端闸门走不到不等于没有任何断言走得到。**把「端到端测不了」写成「测不了」，
  是这一节最容易犯的错。**
  代价是实测的：原来那两条断言喂的 `area` 原点全是 `(0,0)`，所以把函数里的 `a.x` /
  `a.y` 整个换成字面量 `0`，**58 条断言一条都不会红**。现在有一条专门喂非零原点的
  工作区（右侧副屏、左侧副屏的负 `x`、顶部任务栏的 `y` 偏移、副屏内坐标原样保留），
  并且自带那个「把原点当成 0」的变异体，要求四组输入全都抓住它。
- **公开镜像里的内容会不会被人从别处推翻。** 审计只在同步那一刻看一眼
  （`mirror.yml` 只挂 `main` 的 push 和手动触发,没有定期复查）。
- **这份清单自己是手写的。** 它追不上新长出来的坑 —— 每次红了都得有人想起来回写它。
  而且如上面那条纪律所说：它列出的每一条**也可能是错的**。定期挑一条造个变异体试试。
